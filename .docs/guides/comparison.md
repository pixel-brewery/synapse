# Choosing a CLI AI integration library

Synapse focuses on the boundary between a local application and its installed AI CLIs: independent application/account profiles, coordinated credential changes, owned execution and session lifecycle, and policy-controlled routing. Other libraries make useful choices around agent breadth, small execution APIs, typed workflows or AI SDK interoperability.

This is a source review dated **2026-10-29**, not a benchmark or an exhaustive audit. **Documented** describes the cited public contract or implementation. **Unverified** means the reviewed sources did not establish the equivalent guarantee; it does not mean a project cannot provide it. Synapse's own platform and live-account evidence is described in the [compatibility guide](cli-compatibility.md).

| Requirement                                                  | **Synapse**                                                                                 | Agents Wire                                                         | Coding Agent Runner           | Unigent                                                                                | Agent CLI SDK                           |

| Drain work before credential mutation                        | **Shared coordinator blocks admission, drains runs and advances persisted auth generation** | Equivalent guarantee unverified                                     | Host responsibility           | Equivalent guarantee unverified                                                        | Equivalent guarantee unverified         |

Synapse's coordinator is shared by the runtimes/auth managers composed in one host. It is not a cross-application background service or a global lock between unrelated OS processes. The [auth](../../libs/synapse-auth/README.md) and [runtime](../../libs/synapse-runtime/README.md) contracts describe that scope and incomplete-cleanup behavior.

Provider counts describe the reviewed definitions, not equivalent authentication, policy or session support. Synapse's ACP adapter also requires agent-specific capability negotiation, trusted permission mappings and, when needed, an injected native auth adapter.

Important source details:

- Agents Wire already has a [bounded async queue](https://github.com/pivanov/agents-wire/blob/7a6c96bd005e863bc0cf6070af8af235bd3fe257/packages/agents-wire/src/internal/async-queue.ts) and substantial orchestration. Its [failover options](https://github.com/pivanov/agents-wire/blob/7a6c96bd005e863bc0cf6070af8af235bd3fe257/packages/agents-wire/src/orchestrate/failover.ts) use error classification and an optional retry predicate; the inspected contract does not require Synapse's explicit repeatability/write policy.
- Coding Agent Runner's [runner implementation](https://github.com/yinguangyao/coding-agent-runner/blob/66f96bd6eeabfdb007d04e29f44403a2d4d0f424/src/agent-runner.ts) and [CI workflow](https://github.com/yinguangyao/coding-agent-runner/blob/66f96bd6eeabfdb007d04e29f44403a2d4d0f424/.github/workflows/ci.yml) support the bounded scope above. The TypeScript package is distinct from the unrelated .NET project with a similar name.
- Unigent's [backend contract](https://github.com/gintasz/unigent/blob/b7648eb927554cb311a4a0114aeab413268d9cd1/packages/unigent-core/src/backend.ts) is an extension seam. Its [Codex adapter](https://github.com/gintasz/unigent/blob/b7648eb927554cb311a4a0114aeab413268d9cd1/packages/unigent-adapter-codexcli/src/index.ts) preserves native authentication in clean configuration. Clean configuration alone does not establish an independent application/account credential lifecycle.
- Agent CLI SDK's README emphasizes Claude and Codex. Its [current dispatcher source](https://github.com/jnarowski/agentcmd/blob/main/packages/agent-cli-sdk/src/index.ts) also includes Gemini; this source observation is separate from testing the published 1.3.1 package.

Check each package's actual peers and native transport. In particular, Synapse's characterized OpenCode 1.18.31 CLI path is a different interface from the OpenCode 2.x server/client adapter above.

## Choosing deliberately

Choose **Synapse** when account ownership, coordinated credential changes and persistent session binding are central application requirements, and you want routing and drivers as separate packages. Its initial provider set is deliberately smaller than Agents Wire's; native Windows CI and live-account evidence still need to be established for a public release.

Choose **Agents Wire** when its broader agent definitions, pools and orchestration match a POSIX/WSL host. Choose **Coding Agent Runner** when a small execution layer is enough and your host already handles auth and queues. Choose **Unigent** when typed completions and workflow composition are the desired developer interface. Consider **Agent CLI SDK** for its native execution and history surface, or an **AI SDK provider** when compatibility with an existing AI SDK application is the priority.

[T3 Code](https://github.com/pingdotgg/t3code) is also a useful application architecture reference for instances, authentication and session lifecycle. It serves a different role from a reusable CLI runtime package. Synapse's reference decisions and independent implementation boundaries are documented in the [architecture guide](../architecture/synapse.md) and [NOTICE](../../NOTICE.md).
